================================================================================
  QQ 机器人部署过程 · NapCat + DeepSeek API
  项目：qq-deepseek-bot（用你的 QQ 小号跑一个 DeepSeek 驱动的聊天机器人）
================================================================================

一句话说明：
  你的 QQ 小号  <-收消息/发消息->  NapCat（把 QQ 协议翻译成 OneBot 11）
                <-WebSocket->  本机器人（Node.js）  <-HTTP->  DeepSeek API

  ┌────────┐    QQ 协议    ┌────────┐   OneBot 11    ┌──────────┐   HTTP    ┌─────────┐
  │ QQ 小号 │ <──────────> │ NapCat │ <────WS──────> │ 本机器人  │ ────────> │ DeepSeek │
  └────────┘               └────────┘                └──────────┘           └─────────┘
  手机/桌面登录              消息收发协议层              记忆/触发/人设         大模型

  分工：NapCat 负责"让程序能收发 QQ 消息"，本机器人负责"决定回什么"，
        DeepSeek 负责"生成内容"。三者通过两个标准接口衔接，互不依赖。
================================================================================

你需要准备什么
--------------------------------------------------------------------------------
  1. 一个 QQ 小号（建议平时不用的号；机器人有被封号风险，别用主号）
  2. 一部能扫码的手机（登录小号用）
  3. DeepSeek 平台的 API Key（按量付费，需要充值才能用）
  4. Node.js >= 22.9（本项目已在这台机器验证 Node 24）
  5. 本文件夹里的代码（已写好，下面会教你跑起来）

--------------------------------------------------------------------------------
一、拿到 DeepSeek API Key（5 分钟）
--------------------------------------------------------------------------------
  1. 打开 https://platform.deepseek.com ，注册/登录
  2. 左侧「API Keys」→ 创建 API Key，复制保存好（sk- 开头，只显示一次）
  3. 在「用量/余额」里确认账户有余额（没有的话调用会报 402）
  ★ 本项目默认用 deepseek-v4-flash（推理模型，会先思考再回答）；想要更强可把
    .env 里 DEEPSEEK_MODEL 改成 deepseek-v4-pro。
  参考文档：https://api-docs.deepseek.com/zh-cn/


--------------------------------------------------------------------------------
二、安装 NapCat（两条路线任选其一）
--------------------------------------------------------------------------------
★ NapCat 更新很快，具体版本号和界面文字以官方文档为准：
  https://doc.napneko.icu （官方） / GitHub 搜 NapCatQQ 的 Releases

【路线 A：Windows + 桌面 QQ（新手推荐，和本机器人同机跑）】
  1. 在 Windows 上装好并登录「QQ」桌面客户端（NT 版），登录你的小号
  2. 从 NapCat 官方下载页拿到安装包/一键安装器，装好后启动
  3. NapCat 会接管那个已登录的 QQ；启动后打开它的 Web 管理面板
     （默认 http://127.0.0.1:6099）
  4. 在面板里确认它已经连上了你的小号（没连上就点"登录/扫码"，用手机扫码）

【路线 B：Linux / Docker 无头部署（没有桌面环境时）】
  1. 服务器上跑：
       docker run -d --name napcat \
         -e ACCOUNT=你的小号QQ号 \
         -p 6099:6099 \
         mlikiowa/napcat-docker:latest
     （镜像名和参数以官方 README 为准，可能随版本变化）
  2. 打开 http://服务器IP:6099 用手机扫码登录小号
  3. 注意：Docker 里的 NapCat 要连回你的机器人，地址不能写 127.0.0.1，
     要写宿主机的局域网 IP 或 host.docker.internal

--------------------------------------------------------------------------------
三、配置 OneBot 反向 WebSocket（让 NapCat 连到本机器人）
--------------------------------------------------------------------------------
  NapCat 的 Web 面板里找到「网络配置 / OneBot」相关设置，新建一个 OneBot 11 服务：

    连接方式    ：反向 WebSocket（也叫"反向 ws 服务端/主动连接"）
    协议        ：OneBot v11
    WebSocket 地址：ws://127.0.0.1:3001/onebot/v11/ws
                    （Docker 部署改成宿主机的 IP）

  保存后 NapCat 会主动来连本机器人。3001 这个端口和 /onebot/v11/ws 路径
  与本项目 .env 里的 BOT_WS_PORT / BOT_WS_PATH 一一对应，两边改要一起改。

  验证连接：等机器人启动后，机器人终端会打印「NapCat 已连入」。


--------------------------------------------------------------------------------
四、配置本项目（.env）
--------------------------------------------------------------------------------
  在本文件夹里：

    Windows PowerShell：
        Copy-Item .env.example .env
    或 cmd：
        copy .env.example .env

  然后用记事本/VS Code 打开 .env，至少改两处：

    DEEPSEEK_API_KEY = sk-你第一步申请的Key
    DEEPSEEK_MODEL   = deepseek-v4-flash     # 想要更强改 deepseek-v4-pro

  其它项都有默认值，看不懂的先别动，含义见 .env.example 里的注释。


--------------------------------------------------------------------------------
五、启动机器人
--------------------------------------------------------------------------------
    cd C:\Users\AppleRepair\Desktop\qq-deepseek-bot
    npm install      # 首次装依赖（只有一个 ws 包，几秒）
    npm start        # 启动

  看到类似输出即成功：

    机器人已启动：ws://127.0.0.1:3001/onebot/v11/ws
    模式：正式　模型：deepseek-v4-flash

  之后若 NapCat 也配好了，会再打印一行「NapCat 已连入」。


--------------------------------------------------------------------------------
六、测试
--------------------------------------------------------------------------------
  1. 用你手机上的主号（或别人）给机器人小号发私聊：随便说句话，它应该回复
  2. 把机器人小号拉进一个群，@ 它 或 发以 / 开头的消息，它才回（默认 at_or_prefix）
  3. 发 /reset 清空这段对话的记忆；发 /help 看帮助

  ★ 想在花钱之前先验证"NapCat 到机器人"这段链路通不通：
      把 .env 里 BOT_DRY_RUN 改成 1，重启机器人。
      这时机器人不调用 DeepSeek，收到什么就回「[DRY-RUN] 收到：……」。
      链路通了之后再改回 0，正式调用大模型。


--------------------------------------------------------------------------------
七、触发规则与内置命令（默认行为）
--------------------------------------------------------------------------------
  - 私聊：总是回复
  - 群聊：默认 at_or_prefix（@机器人 或 以 / 开头才回），避免群里刷屏
    想在群里"每条都回"，把 .env 里 BOT_TRIGGER_MODE 改成 all
  - /reset 或「重置」：清空当前会话记忆
  - /help 或「帮助」：显示帮助
  每个会话独立记忆：私聊按人、群聊按群，最多保留 BOT_MAX_HISTORY 条（默认 12）


--------------------------------------------------------------------------------
八、目录结构与代码说明
--------------------------------------------------------------------------------
  index.js            入口：起反向 WebSocket 服务，收 NapCat 事件
  lib/config.js       读 .env（全部带默认值）
  lib/memory.js       对话记忆（每会话一份，带长度上限）
  lib/deepseek.js     调 DeepSeek 接口（内置 fetch，无 SDK 依赖）
  lib/message.js      消息解析：取文本、判断 @、判断触发、超长分段
  lib/bot.js          核心逻辑：命令处理、组装上下文、回复
  test/unit.mjs       无网络单元测试（npm test）
  test/simulate.mjs   模拟 NapCat 的联调客户端（npm run simulate）
  .env.example        配置模板

  依赖只有一个：ws（实现 WebSocket 服务）。大模型调用直接用 Node 内置 fetch，
  不引第三方 SDK，方便你读和改。


--------------------------------------------------------------------------------
九、常见问题排查
--------------------------------------------------------------------------------
  1. 机器人起了，但 NapCat 一直没连上
     - 检查 NapCat 面板里反向 WS 地址是否写对（端口、路径、协议 ws://）
     - NapCat 和机器人是不是同一台机器；Docker 下 127.0.0.1 不通，要换宿主机 IP
     - 防火墙放行 3001 端口

  2. 连上了，但群里/私聊没反应
     - 群聊默认要 @ 或用 / 开头；私聊应该直接回，先测私聊
     - 把 BOT_DRY_RUN 改成 1 重启，排除 DeepSeek 的因素：dry-run 有回显=链路 OK，
       没回显=触发规则或 NapCat 事件没进来

  3. 回「DeepSeek 返回 401」
     - API Key 填错/漏填/被删。检查 .env，Key 前面别少 sk-

  4. 回「DeepSeek 返回 402 / 429」
     - 402 余额不足，去平台充值；429 触发限流，稍等或降低频率

  5. 回复很长、被截断或分成了好几条
     - 本机器人会按 BOT_REPLY_MAX_CHARS 自动分段；把 max_tokens 或温度改了试试
       （在 lib/deepseek.js 里）

  6. 想换个"人设"
     - 改 .env 里的 BOT_SYSTEM_PROMPT，比如"你是……，说话……"


--------------------------------------------------------------------------------
十、安全与风险（请务必看）
--------------------------------------------------------------------------------
  1. ★ 账号风险：用机器人登录 QQ 属于第三方协议接入，存在被腾讯风控/封号的可能。
     务必用小号，且不要高频群发、不要发广告/违规内容，否则小号很容易没。
     这属于灰色地带工具，本项目只用于你个人学习与自用。
  2. ★ API 计费：DeepSeek 按 token 计费，机器人是"每句都算一次上下文"，聊得久
     token 会滚上去。BOT_MAX_HISTORY 设小一点（默认 12）能省不少；别把机器人
     公开挂到大群里，否则可能一夜之间消耗大量额度。
  3. 不要把 .env 提交到 Git（已写进 .gitignore），Key 泄露会被盗刷。
  4. 内容合规：别让机器人自动生成违规内容；大模型回复前最好自己先过一遍。
  5. 本项目是"最简可跑"的实现：单进程、内存记忆（重启就忘）、无鉴权。
     如果以后要给别人用，再加：鉴权、持久化记忆、频率限制、敏感词过滤。


--------------------------------------------------------------------------------
十一、本地免联调自测（不碰 QQ、不花钱）
--------------------------------------------------------------------------------
  1. 逻辑自测（不发任何网络请求）：
        npm test
     会跑 5 组断言：私聊回复、群聊触发、@ 触发、命令、记忆上限。

  2. 真·WebSocket 联调（模拟 NapCat，不碰真实 QQ）：
        先在一个终端：  $env:BOT_DRY_RUN='1'; npm start
        再开一个终端：  npm run simulate
     看到「收到机器人回复 + 联调成功 ✓」即说明 WS 链路和消息处理都正常。

  这套自测的意义：把"机器人写得对不对"和"NapCat/DeepSeek 配得对不对"分开排查，
  出问题时能快速定位是哪一层的问题。
